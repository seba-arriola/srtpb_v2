# SRTPB v2 — Seedlink Real-Time Playback

## A tool for simulating a real time playback of seismic data.

This code mimics a real-life scenario of a seismic data stream by resending
archived seismic data to a SeedLink / Datalink server (e.g. Iris Ringserver) as
if it were real time. It reads archived waveforms, slices them into small time
intervals (`PacketTimeInterval`), and transmits each slice respecting the
natural timeline, optionally accelerating time and/or simulating per-station
telemetry latencies.

---

## About this repository (v2)

This is an **updated fork of the original [SRTPB](https://github.com/rannof/srtpb)**
project by **Ran Novitsky Nof** (BSD/IGPP, `ran.nof@gmail.com`), released under
the **GNU Lesser General Public License v3** (see `LICENSE`).

The original project was written for **Python 2.7** and has not been updated in
over 10 years. This v2 repository keeps the same architecture but **modernizes it
and fixes issues**, so it builds and runs on current machines:

- **Python 3 support** (original required Python 2.7):
  - `src/srtpblib.i` — SWIG typemap so the C layer accepts Python `bytes`.
  - `src/Makefile` — builds with `python3-config` and produces `_srtpblib.so`.
  - `src/srtpb.py` — ported to Python 3 (`io.BytesIO`, `xrange`, bytes handling, ...).
- **New `-ti` / `-tf` options**: cut the replay to a time window of the day
  (`hh:mm:ss[.f]`). Data outside the window is not sent. Useful to skip long
  lead-in periods where only low-rate channels (e.g. `L*` 1 Hz) are active.
- **Packet-level interleaving fix**: each time window is now sent with correct
  per-channel record start/end times, so all active channels of a window
  (e.g. `HH`, `LH`, `LN`) stream together instead of sequentially.
- **C replay engine** (`src/srtpbc.c`): the real-time loop now runs in C using
  libmseed and libdali.  It reads MiniSEED directly, slices traces by sample
  index, packs 512-byte STEIM2 records and batches DataLink writes.  The old
  ObsPy-per-trace loop could not keep up with thousands of channels in real
  time; the C engine keeps the lag bounded (typically a few milliseconds).
  `src/srtpb.py` remains the same command-line front-end.
- **`checkmseed.py`**: helper to inspect MiniSEED files (headers only) and
  recommend `-ti` / `-tf` values so every band is active during the replay.
- **`AGENTS.md`**: development/usage notes including the recommended 3-terminal
  workflow.

## Dependencies

### System packages (Debian/Ubuntu example)
```bash
sudo apt install gcc make swig python3 python3-dev python3-venv
```
- `swig` — generates the Python/C bridge from `src/srtpblib.i`.
- `python3-dev` — provides `python3-config`, needed by `src/Makefile`.
- `gcc`, `make` — compile the bundled IRIS tools and the C wrapper.

### Python packages
```bash
python3 -m venv srtpb && source srtpb/bin/activate
pip install -r requirements.txt
```
(`numpy` and `obspy` are listed in `requirements.txt`.)

### Bundled third-party C software (included as tar.gz)
The repository bundles the original IRIS tools as `tar.gz` files. They are
**never modified**: `./INSTALL` extracts and patches only their build settings
(`Makefile` + `CFLAGS = -fPIC`) automatically:

- `ringserver-2014.269.tar.gz` — IRIS Ringserver (SeedLink/Datalink server).
- `dalitool-2013.280.tar.gz` — libdali + dalitool (Datalink protocol client).
- `slinktool-4.2.tar.gz` — slinktool (SeedLink client for monitoring).

The extracted `ringserver/` directory is **regenerated by `./INSTALL`** and is
not part of the repository.

## Installation

From the project root:

```bash
./INSTALL     # extracts the tar.gz, patches build settings, runs make
make          # compiles srtpbc, the SWIG wrapper and msrtslice
```

When finished, all executables and Python files are deployed to `bin/`,
including the C replay engine `bin/srtpbc`.

---

## Running

Once you have waveform files ready, start a SeedLink server with Ringserver:

```bash
bin/ringserver bin/ring.conf
```

Then start the playback on another terminal:

```bash
python bin/srtpb.py [commandline options] PATH
```

The command line is unchanged.  The Python front-end locates `srtpbc` next
to itself (or in `src/srtpbc`) and runs the C replay engine.  If it cannot
find the engine, run `make` from the repository root.

And on a third terminal you can watch the packets arrive:

```bash
bin/slinktool -p localhost:18000
```

Programs that need the waveforms connect to the ringserver the same way. See
`AGENTS.md` for the full 3-terminal workflow, and the ringserver documentation
for additional help.

## Usage

```
srtpb.py [-h] [-t Start [END]] [-ti hh:mm:ss] [-tf hh:mm:ss]
             [-o options [options ...]] [-s seconds] [-l Latency] [-m] [-f]
             [-H Host] [-P Port] [-O file] [-v] [-d delay] [-n processors]
             [--test]
             PATH [PATH ...]

positional arguments:
  PATH                  Path of data (use quotes for "PATH" if using regex)

options:
  -h, --help            show this help message and exit
  -t Start [END]        Start and end times. See obspy.UTCDateTime for
                        acceptable string formats. Usually YYYYMMDDhhmmss.f.
                        Default - None
  -ti hh:mm:ss          Initial time of day to start the replay (hh:mm:ss or
                        hh:mm:ss.f). Data before this time will not be sent.
                        Default - None
  -tf hh:mm:ss          Final time of day to stop the replay (hh:mm:ss or
                        hh:mm:ss.f). Data after this time will not be sent.
                        Default - None
  -o options [options ...]
                        additional optional parameters. The C engine reads
                        MiniSEED directly; only format=MSEED is validated.
  -s seconds            Packet time interval in seconds. Default - 1 sec.
  -l Latency            Latency of data. Can be one argument for all stations
                        in seconds or a file name containing a list of
                        net.sta=X format. Default - 0.
  -m                    Modify time to current time (relative to playback
                        start time)
  -f                    Fast replay - No delay (Not a "real time" playback)
  -H Host               Host Address (127.0.0.1)
  -P Port               Port Number (16000)
  -O file               send output to file
  -v                    Verbose (False).
  -d delay              Directly stream ordered file to server with delay (in
                        seconds) every 250 packets.
  -n processors         Accepted for compatibility; the C engine is
                        single-process
  --test                Testing mode - no data will be sent. (False)
```

Example — replay only the busy window of `test2.mseed`, starting all channels
together in real time:

```bash
python bin/srtpb.py -s 1.0 -m -ti 22:49:28 -tf 23:49:32 test2.mseed
```

Note: the `-t` option uses `nargs='+'`, so the `PATH` argument must come
*before* the `-t` arguments.

# MSRTSLICE
## A tool for preparing archived data for replays.

This C code reads mseed files and sends them to a mseed output file or a
datalink server. It slices the data into 1-second slices and reorganizes the
data according to the start time of each slice. It can handle large amounts of
data and is pure C. Use `-h` for help. It is part of the srtpb package.
